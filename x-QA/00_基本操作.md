# stackup QA

## Angularはどのコマンドで起動しますか？

プロジェクトルートで次を実行します。

```bash
corepack pnpm web:start
```

実際には、`apps/web`で次のコマンドが実行されます。

```bash
ng serve --host 0.0.0.0 --port 4200
```

アクセス先は `http://localhost:4200` です。

## ClearML Serverはどのコマンドで起動しますか？

```bash
corepack pnpm backend:up
```

ClearML標準Web画面は `http://localhost:8080`、APIは `http://localhost:8008` です。

## PrimeUIライセンスはどこに設定しますか？

`apps/web/.env` に設定します。

```dotenv
PRIMEUI_LICENSE=取得したライセンスキー
```

`apps/web/.env` はGit管理対象外です。サンプルとして `apps/web/.env.example` を管理しています。

ライセンスキーはAngularのブラウザ向けバンドルに含まれるため、このファイルにはPrimeUIライセンスキー以外の秘密情報を設定しないでください。

## Angularで使用するnpmパッケージはどこに追加しますか？

`apps/web/package.json` に追加します。

通常の依存パッケージは次のコマンドで追加します。

```bash
corepack pnpm --dir apps/web add パッケージ名
```

開発時だけ使用するパッケージは次のコマンドで追加します。

```bash
corepack pnpm --dir apps/web add -D パッケージ名
```

ロックファイルはプロジェクトルートの `pnpm-lock.yaml` が更新されます。

## ルートのpackage.jsonは何に使用しますか？

プロジェクト全体の共通コマンドを管理します。Angular固有のライブラリは、原則として `apps/web/package.json` で管理します。

## `features/experiments`はAngularやClearMLの標準フォルダですか？

Angularの標準フォルダではありません。ClearML Webのソースコードに含まれる、実験やタスクを管理する機能をまとめたfeatureフォルダです。このプロジェクト独自に追加したものではありません。

## ClearMLのデータはどこに保存されますか？

このプロジェクトのClearML ServerはPostgreSQLを使用していません。データの種類に応じて、次の保存先を使用します。

| 保存先 | 主なデータ |
| --- | --- |
| MongoDB | プロジェクト、タスク、Dataset、Modelなどのメタデータ |
| Elasticsearch | 実験ログ、スカラー指標、検索用データ |
| Redis | キャッシュや一時的な処理データ |
| ClearML File Server | 画像、モデルファイル、Artifact、Datasetの実ファイル |

それぞれのデータは、Dockerの次のnamed volumeに保存されます。

```text
clearml-mongo-db
clearml-elasticsearch
clearml-redis
clearml-files
```

半導体学習用データを追加する場合、タスクやパラメータなどの情報はMongoDBなどへ保存され、画像、モデル、Artifactなどの実ファイルは `clearml-files` へ保存されます。

```bash
corepack pnpm backend:down
```

上記の通常の停止操作ではvolumeが残るため、データも保持されます。`docker compose down -v` などでvolumeを削除すると、保存したデータも削除されます。

Docker volume内のファイルを直接操作せず、原則としてClearML APIまたはClearML SDK経由で登録・取得します。
